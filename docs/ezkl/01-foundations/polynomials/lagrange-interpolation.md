# 求值与拉格朗日插值

> **核心** ｜ 前置：01_数学地基/01_有限域/02_素域GF(p)与乘法逆元

**一句话**：n 个点唯一确定一个 n−1 次多项式；电路里的每一行就是一个点。

**打个比方**：给你几个路标，只能画出一条最平滑的路正好穿过它们。那条路就是多项式，路标就是电路的每一行。

**在 EZKL 里的落点**：电路行 → 多项式，是所有「多项式证明」的起点。

    给 3 个点，写出过它们的二次多项式。

> 读完约 8 分钟。这一篇是「算术化」那层的入口，务必弄懂「行 → 点」这个映射。

## 一、问题

电路有 65536 行，每行一条约束。你想让验证者相信「每一行都成立」。

逐行验？那要验 65536 次，比重新算一遍还慢。

有没有办法**把它们打包成一个东西**，一次验完？

有。这个「东西」就是多项式。

## 二、把行号当 x，把值当 y

这是全部技巧的核心，只有一句话：

> **第 i 行，就是 x = ωⁱ 这个点。**

于是「65536 行」就变成了「65536 个点」。而数学告诉我们：

> **n 个点唯一确定一个次数不超过 n−1 的多项式。**

所以「每一行都对」 ⟺ 「这些点都在这个多项式上」。验多项式，比验 65536 行便宜得多。

## 三、怎么从点算出多项式：拉格朗日插值

公式长这样（不用背，看结构就够）：

> L_i(x) = ∏_{j≠i} (x − x_j) / (x_i − x_j)
> P(x) = Σ y_i · L_i(x)

看不懂没关系。它的意思很朴素：**L_i 是一个「只在第 i 个点等于 1、其他点都等于 0」的开关**。所以把每个 y_i 乘上它自己的开关，加起来，就穿过了所有点。

## 四、拿纸算一个

三个点：(0, 1)、(1, 3)、(2, 7)。求过它们的多项式。

猜一个二次的 P(x) = ax² + bx + c：

- x=0：c = 1
- x=1：a + b + 1 = 3 → a + b = 2
- x=2：4a + 2b + 1 = 7 → 4a + 2b = 6 → 2a + b = 3

两式相减：a = 1，于是 b = 1。

> **P(x) = x² + x + 1**

验：x=0→1 ✓，x=1→3 ✓，x=2→7 ✓。

**唯一性**：你能找到另一个二次多项式也穿过这三个点吗？找不到。这不是巧合，是代数基本定理的直接推论。

## 五、为什么 EZKL 的电路行数必须是 2 的幂

因为实际实现不在「0,1,2,3…」这些点上插值，而是在**单位根**上：

> ω, ω², ω³, …, ωⁿ = 1，其中 ωⁿ = 1

用单位根的好处：插值和求值都能用 **NTT**（有限域上的快速傅里叶变换）做到 O(n log n)，而且完全可并行。NTT 要求 n 是 2 的幂。

所以 `logrows = 16` 就是 65536 行，`logrows = 17` 就是 131072 行 —— 只能翻倍，不能取 100000。这也是为什么「加一层网络」可能让 k 直接跳一级，成本翻倍。

## 六、落到 EZKL 上

- `model.compiled` 里存的是约束系统的结构；
- `settings.json` 里的 `num_rows` 就是「有多少个点」；
- halo2 内部会给这些点分配一个 **domain**（求值域），所有多项式运算都在这个域上做；
- `num_rows` 估小了会直接编译失败（约束装不下），估大了白白多花钱。

## 七、一个容易混的点

插值**不是**统计学里的「拟合曲线」。

拟合是「找一条大致穿过这些点的线，允许偏差」。
插值是「找那条**精确**穿过每个点的线，唯一且不允许偏差」。

在 ZK 里必须是后者：差一个点，就说明有一行约束不成立，整个证明就该失败。

## 八、自检答案

> 问：给 3 个点，写出过它们的二次多项式。

答：取 (0,1)、(1,3)、(2,7)，设 P(x)=ax²+bx+c。由 x=0 得 c=1；由 x=1 得 a+b=2；由 x=2 得 4a+2b=6。解得 a=1、b=1，故 P(x)=x²+x+1。验三点均成立，且二次多项式由三点唯一确定。

## 九、一句话记住

**行就是点，点就是多项式。把「逐行检查」变成「检查一个多项式」，是全部算术化的起点。**
