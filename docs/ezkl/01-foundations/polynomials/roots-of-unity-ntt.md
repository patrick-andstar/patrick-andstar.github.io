## 一、单位根是什么

在复数里，方程 xⁿ = 1 有 n 个解，均匀分布在单位圆上。

在有限域里也一样：如果 n 整除 p−1，就存在 n 个「n 次单位根」，它们也均匀分布（在乘法群的意义上）。

记其中一个为 ω，那么全部是：

> 1, ω, ω², ω³, …, ω^(n−1)

它们有一个漂亮的性质：**两两不同，且加起来等于 0**（当 n > 1 时）。

## 二、为什么要用它们

因为插值和求值要在这些点上做。

回忆 `01/04/01`：n 个点唯一确定一个 n−1 次多项式。那选哪些点？

- 选 0,1,2,3…：插值公式很丑，求值要 O(n²)；
- 选单位根：插值和求值都能用 **NTT** 做到 O(n log n)。

**NTT = 有限域上的快速傅里叶变换。** 它的结构和 FFT 一模一样，只是把复数换成了域元素。

## 三、NTT 快在哪

朴素求值：n 个点，每个点算 n 次乘加 → O(n²)。

NTT：用「分治」把问题拆成两半：

> 把多项式按奇偶次项拆开：P(x) = P_even(x²) + x·P_odd(x²)

因为 ω² 也是单位根（只是阶数减半），所以两半可以递归地在「一半的点」上算。

递归 log n 层，每层 O(n) 次运算 → **O(n log n)**。

而且每一层都是「成对的两个数做一次蝶形运算」，**完美并行**。

## 四、为什么必须 n = 2^k

因为分治要一直对半分，直到长度 1。

- n = 65536 = 2¹⁶ → 能对半分 16 次，正好；
- n = 100000 = 2⁵ × 5⁵ → 分不干净，NTT 要退化成混合基，实现复杂、常数大。

所以工程上统一取 2 的幂。**这就是 `logrows = 16` 的含义：2¹⁶ = 65536 行。**

## 五、代价：台阶效应

只能取 2 的幂，意味着：

| 想要的行数 | 实际分配 |
|---|---|
| 40,000 | 65,536（k=16） |
| 70,000 | 131,072（k=17） |
| 300,000 | 524,288（k=19） |

多一行装不下，就得多付一倍（`03/01/02`）。

这也是为什么「模型小改一版，证明时间翻倍」——不是变慢了，是跨了台阶。

## 六、在 EZKL 里

- halo2 内部维护一个 `domain`，记录 ω 和 n；
- 所有多项式运算都在这个 domain 上做；
- `settings.json` 的 `logrows` 直接决定 domain 大小；
- SRS 也必须至少有 n 个点（因为要承诺 n 次多项式）。

三者是绑死的：**domain 大小 = 2^k = SRS 点数 = 行数上限**。

## 七、一个容易误解的点

「NTT 是一种压缩算法」——不对。

NTT 是**变换**，不是压缩：它把「系数表示」换成「点值表示」，信息量不变（两者可以无损互转）。

它的价值是让「多项式乘法」从 O(n²) 变成 O(n log n)：在点值表示下，乘法就是逐点相乘。

## 八、自检答案

> 问：说清「为什么电路行数必须是 2 的幂」，以及 NTT 省掉了多少计算。

答：因为插值和求值要在 n 次单位根上做，而快速算法（NTT）依赖「不断对半分」的分治结构，只有 n 是 2 的幂时才能干净地分到底；否则要退化成混合基实现，复杂度和常数都不划算。NTT 把多项式求值/插值从 O(n²) 降到 O(n log n)：65536 行时约从 43 亿次降到 100 万次量级。

## 九、一句话记住

**单位根让插值变快，NTT 让插值变 O(n log n)，2 的幂让 NTT 能对半分。三者绑死。**
