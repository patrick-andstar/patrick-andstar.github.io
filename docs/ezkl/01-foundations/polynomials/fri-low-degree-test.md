## 一、目标

给定一个多项式 p（通过它的求值表），要证明：

> **p 的次数不超过 d。**

这件事为什么重要？因为 `01/04/03` 说过：如果 p 的次数超了，它就能在更多点上「碰巧为零」，可靠性就崩了。

KZG 靠「承诺 + 配对」间接保证次数；FRI 靠**反复折叠 + 抽查**直接验。

## 二、折叠：把次数减半

假设 p(X) 的次数是 d，把它按奇偶拆开：

> p(X) = p_even(X²) + X · p_odd(X²)

两个新多项式的次数都是 d/2。

取一个随机数 α，组合成：

> p'(X) = p_even(X) + α · p_odd(X)

**p' 的次数也是 d/2。**

关键性质：如果 p 的次数真的 ≤ d，那 p' 的次数也 ≤ d/2；如果 p 的次数超了，p' 超的概率极高（随机 α 使坏项无法抵消）。

## 三、反复折叠

对 p' 再做一次 → d/4；再做 → d/8……

log₂(d) 轮之后，次数变成 1，也就是一个常数。

最后一轮，验证者直接要那个常数，检查它等于预期值。

**所以整个协议是：折叠 log d 次，最后验一个常数。**

## 四、抽查：怎么保证折叠没作假

光折叠不够 —— 证明者可能在每一步给假的求值表。

所以每一轮，验证者随机挑几个位置，要求证明者提供「这个位置的值 + Merkle 路径」。

- 如果证明者给的折叠结果和原表不一致，抽查会露馅；
- 抽查的漏检概率随抽查次数指数下降。

**这就是「低度测试」：不是证明次数低，而是用抽查把「次数虚高」的概率压到可忽略。**

## 五、代价对比

| | FRI（STARK） | KZG |
|---|---|---|
| 需要可信设置 | **不要** | 要 |
| proof 大小 | O(log² d) 个哈希，几十 KB | **33 字节** |
| 验证时间 | O(log² d) 次哈希 | 2 次配对 |
| 后量子安全 | **是**（只依赖哈希） | 否 |

以 d = 2²⁰ 为例：

- FRI 的 proof 约 100–300 KB；
- KZG 的 proof 33 字节。

**差三个数量级。** 这就是为什么 EZKL 选 KZG：它要「1 秒验证 + 小 proof」，而不是「免信任」。

## 六、一个容易误解的点

「FRI 不用可信设置，所以更安全」——不严谨。

- FRI 免除了「τ 被保留」的假设；
- 但它引入了另一个假设：哈希函数是抗碰撞的（而且需要更强的「随机预言机」性质）；
- 同时它对「域的大小」和「抽查次数」有严格要求，参数配错一样不安全。

所以是**换了一组假设**，不是「没有假设」。

## 七、自检答案

> 问：一句话说出 FRI 与 KZG 的核心差别（证明大小 / 是否需要可信设置）。

答：KZG 需要可信设置，但 proof 恒定 33 字节、验证两次配对；FRI 不需要可信设置（只依赖哈希），但 proof 是 O(log²d) 个哈希、几十到几百 KB，验证要算同样多的哈希。前者快而小但要多信一次仪式，后者免信任但笨重。

## 八、一句话记住

**FRI 用「折叠 + 抽查」代替「承诺 + 配对」。免了信任，付了体积。**
