# BN254的两层域

> **核心** ｜ 前置：01_数学地基/01_有限域/02_素域GF(p)与乘法逆元

**一句话**：标量住在 Fr（约 2^254 的素域），曲线坐标住在 Fq，两者不是一个域，不能混着算。

**打个比方**：把电路想成一张 Excel：格子里的数（Fr）和用来盖章的坐标（Fq）是两套不同的单位，不能混着填。混了不会报错，会算出一个谁也验不过的结果。

**在 EZKL 里的落点**：halo2curves::bn256::{Fr, G1Affine}：见证是 Fr，承诺是 G1 点。

## 一、一条曲线上有两套数

EZKL 用的曲线叫 BN254。它的方程很简单：

> y² = x³ + 3

曲线上的一个点 (x, y)，坐标 x、y 都是某个大素数域里的数。这个域叫 **Fq**（q 是那个素数）。

同时，这条曲线上有一类操作：把一个点「自加」k 次，记作 k·P。这里的 k 是整数，取值范围由曲线的**阶 r** 决定——因为 r·P 会回到「无穷远点」（相当于零）。

所以 k 天然是「模 r」的数。这个域叫 **Fr**。

> **一句话：Fq 管坐标，Fr 管数量。**

## 二、为什么标量要模 r

假设 r = 7（真实值约 2²⁵⁴，这里缩小看）。那么：

1·P, 2·P, …, 6·P, 7·P = O（无穷远点）, 8·P = 1·P …

也就是说，k 和 k+7 得到的是**同一个点**。所以「k 是多少」这个问题，答案只在 0..6 里有意义。

这就是为什么标量住在 Fr：不是人为规定，是数学上它只能这么活。

## 三、两个域看起来一样，其实不能混

| | Fr | Fq |
|---|---|---|
| 存什么 | 标量、见证值、电路里的每个格子 | 曲线点的坐标 |
| 模数 | 曲线的阶 r | 基域的素数 q |
| 典型大小 | ≈ 2²⁵⁴ | ≈ 2²⁵⁴ |
| 在 EZKL 里 | `witness.json` 里的数 | `proof.json` 里的 `0x…` |

两者数值范围接近，**所以混用不会报错，只会算出一个谁也验不过的东西**。这是新手最常见的静默错误之一。

## 四、落到具体文件上

- `proof.json` 里那些 `0x` 开头的长串，是**压缩后的 G1 点**：32 字节的 x 坐标 + 1 位符号。它们属于 Fq。
- `witness.json` 里的数是**电路格子的值**，属于 Fr。
- `vk.key` 里两者都有：既有曲线点（承诺），也有域元素（各种常量）。

一个具体后果：你手工改 `proof.json` 里的一个字节，那不是「改了一个数」，而是「改出了一个不在曲线上的点」——验证器会直接拒绝（`06/04/04`）。

## 五、为什么偏偏是 BN254

不是因为最安全（它的安全等级约 100 bit，比 128 bit 的标准略低），而是因为 **EVM 的 `ecPairing` 预编译只认它**。

选型逻辑：如果这套证明要在以太坊上验，曲线就没得选。EZKL 保留了这条能力（虽然你的场景用不到，相关目录已删），所以整条技术栈都锁在 BN254 上。

代价：安全余量比 BLS12-381 小一档。写报告如果要提「128 bit 安全」，得说明这是行业惯例口径，不是这条曲线的严格结论。

## 六、自检答案

> 问：为什么 witness 是域元素，而 proof 里的承诺是曲线点？

答：witness 是这次计算里每个变量的取值，它们是「数量」，要做加减乘除，所以住在标量域 Fr。承诺是把一个多项式「压」成曲线上的一个点，点有坐标，坐标住在基域 Fq。两者是不同层的东西：一个是算出来的数，一个是用来盖章的几何对象。

## 七、一句话记住

**Fr 是算的数，Fq 是盖章的坐标。看起来一样大，混了就废。**
