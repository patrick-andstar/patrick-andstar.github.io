## 一、这棵树是怎么长出来的

**1. 只收 EZKL 真正用到的东西。**
每个叶子都能在源码或产物里找到落点：要么对应一个目录/模块，要么对应一个命令或文件。
找不到落点的（比如 STARK、Groth16 全流程）不进树，只在导读里留一张对照表。
唯一的例外是 `07_机器学习预备`：它不属于 EZKL，但不补它就看不进 `05_zkML层`，所以单独放最后、按需查。

**2. 按「能不能自己算出来」分层，而不是按学科分。**
你零基础，所以第 0 层不碰数学，只建立「谁在证什么」的直觉；
第 1 层才进有限域和椭圆曲线，而且只学到「能看懂 proof.json 里的字节是什么」为止；
形式化定义（可靠性误差、模拟器）压到第 4 层，因为它们只在你需要写论文时才真的用得上。

**3. 每个叶子必须是一道能自检的问题，不是一章教材。**
所以每个 README 里的「自检」都写得像面试题：答得上来就算过，答不上来说明该回头补前置。
这是防止「看懂了但其实没懂」的唯一办法。

**4. 深的地方真的往下切。**
椭圆曲线不是一章，而是四个叶子（点加法 / 标量乘法 / 点的序列化 / 曲线选型）；
查找表也不是一章，而是五个叶子（为什么需要 / Plookup / LogUp / 动态查找 / 表的代价）。
你要的「圆锥曲线相关运算再往下拆」，就是 `01_数学地基/03_椭圆曲线/01_曲线方程与点加法` 这一层。

## 三、三条路径（别按顺序全学）

**路径 A · 最小闭环（约 12 个知识点，2–3 天）**

2. `00_直觉入门/02_零知识的三种动机`

5. `01_数学地基/01_有限域/02_素域GF(p)与乘法逆元`
6. `01_数学地基/03_椭圆曲线/01_曲线方程与点加法`
7. `01_数学地基/03_椭圆曲线/02_标量乘法与离散对数`
8. `02_承诺与哈希/02_承诺方案/01_承诺的隐藏与绑定性`
9. `02_承诺与哈希/02_承诺方案/03_KZG多项式承诺`

走完这条，你就能跟人讲清「EZKL 证的是计算完整性，不证模型好坏；权重写进 fixed 列就绑死模型」——
这两个判断已经足够支撑项目里的技术口径。

**路径 B · 标准路线（约 50 个 ■，4–6 周）**
A 之后按 `01 → 02 → 03 → 04 → 05 → 06` 顺序推，只学 `■`，`○` 遇到再补。
`07_机器学习预备` 不要通读，卡在哪个算子就翻哪一篇（比如看不懂 `05/01/03 卷积与einsum`，就先去 `07/03 卷积`）。
`03 算术化` 和 `02 承诺` 可以并行，它们之间只有一个交汇点（商多项式要用 KZG 承诺）。

**路径 C · 深挖（写论文/改源码才走）**
在 B 之上补 `○` 与 `◇`，重点三处：
`03_算术化/03_查找表/04_动态查找与向量查找`（EZKL 的独特之处）、

`03_算术化/04_电路布局`（要改性能就得动这里）。

## 四、为什么是 Halo2 + KZG（一张表，不建分支）

EZKL 的选择不是「最好的方案」，是「和它的目标最搭的方案」。下面这张表只在别人问你「为什么不用 XX」时用得上，数值都是量级，别当精确值。

| 方案 | 约束长什么样 | 要靠什么承诺 | 要可信设置吗 | proof 大小 | EZKL 用吗 |
|---|---|---|---|---|---|
| Groth16 | R1CS，一个门一次乘法 | 椭圆曲线配对 | 要，而且**每个电路**各来一次 | 极小，约 200 字节 | 不用 |
| **Halo2 + KZG** | **PLONKish，一张表随便排** | **KZG 多项式承诺** | **要，但一份通用 SRS 通吃所有电路** | **小且恒定，本项目 19 KB** | **就是它** |
| Halo2 + IPA | PLONKish | 内积论证 | 不要 | 随电路规模对数增长 | v23 已删 |
| STARK / FRI | AIR，按时间步展开 | 哈希（Merkle） | 不要 | 大，几十到几百 KB | 不用 |
| Bulletproofs | 内积约束 | 内积论证 | 不要 | 对数级 | 不用 |

一句话总结：**Groth16 的 proof 最小，但每换一个模型就要重新做一次可信设置；STARK 不用可信设置，但 proof 大到不适合「1 秒验证」；Halo2 + KZG 落在中间——一份 SRS 通吃，proof 恒定且小，代价是要信那份 SRS。**

## 五、依据与边界（哪些是我核实的）

**已核实（对照本地 v23.0.5 源码）**
- 依赖与曲线：`Cargo.toml` 锁定 `halo2_proofs`（zkonduit 分支，开 `mv-lookup`）、`halo2curves` 的 `bn256`。
- 命令集：`src/commands.rs` 的 `Commands` 枚举（table / gen-witness / gen-settings / calibrate-settings / compile / setup / prove / verify 等）。
- 三类列与选择子：`src/circuit/region.rs`、`src/circuit/table.rs`。
- 五种可见性：`src/graph/vars.rs` 的 `Visibility::{Private, Public, Fixed, Hashed, KZGCommit}`（字符串名 `polycommit`）。
- Poseidon 承诺：`src/circuit/modules/poseidon.rs`、`polycommit.rs`。
- 非线性查表：`src/circuit/ops/lookup.rs` 的 `LookupOp`（Sigmoid/Tanh/Exp/Erf/Div/Sqrt/Pow…）。
- 成本模型数字来自本项目 32 线程实测（`EZKL_ResNet50_时间测试方案.md`）。
