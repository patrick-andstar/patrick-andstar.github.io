# vk绑定结构还是权重

> **核心** ｜ 前置：04_证明系统/03_密钥与产物/01_compile约束系统固化

**一句话**：param_visibility=fixed 时 vk 绑死权重；=private 时 vk 只绑结构，权重走 witness。这一行决定你的系统能不能换模型。

**打个比方**：fixed 等于把模型照片印在身份证上，换张脸就作废；private 只在身份证上写「另附照片」，照片可以换。

**在 EZKL 里的落点**：graph/vars.rs 的 Visibility；gen-settings --param-visibility。

## 一、一个必须先回答的问题

「模型文件完整性」这句话，到底指什么？

有两种完全不同的读法：

- **读法 A**：证明「这次推理用的就是这一份权重文件」（防掉包）；
- **读法 B**：证明「这次推理用的模型结构没被改」（防换架构）。

EZKL 通过 `param_visibility` 这个参数，让你在这两种之间选。**选错了，整个方案的技术口径就是错的。**

## 二、三种配置

| 配置 | 权重在哪 | vk 绑定什么 | 换权重要重跑吗 |
|---|---|---|---|
| `fixed` | fixed 列（编译进电路） | **结构 + 权重** | 要（compile + setup） |
| `private` | advice 列（witness） | 只有结构 | 不用 |
| `hashed` | advice + 承诺进 instance | 结构 + 权重承诺 | 不用（但承诺要更新） |

注意 `hashed` 是折中：权重不进电路，但它的哈希进公开输入，所以「换了权重」这件事会被发现，只是不需要重建电路。

## 三、默认值是 private，这点很关键

EZKL v23 的 `gen-settings` 默认 `param_visibility=private`。

意味着：**如果你不加参数直接跑，得到的 vk 只绑结构。**

后果很直接：

- 攻击者换一版权重，用同一个 vk、同一个电路，照样能生成 verify 通过的证明；
- 你的「模型文件完整性」需求，实际上没有被满足。

要满足读法 A，必须显式：

```bash
ezkl gen-settings -M model.onnx --param-visibility fixed
```

本项目 demo 里就是这么改的，速度没有差别 —— 差别在「换模型时代价极大」。

## 四、两个需求在 EZKL 里是互斥的

你的项目同时有两个要求：

1. 模型文件完整性（要 `fixed`）；
2. 联邦学习每轮换全局模型（要 `private` 或 `hashed`）。

**这两个在 EZKL 里不能同时满足。** 这是必须写进技术方案的硬约束，不是实现细节。

三条出路：

| 方案 | 做法 | 代价 |
|---|---|---|
| 每轮重建 | 每轮 compile + setup | 4–5 秒/轮，可接受；但 pk 265 MB 要重新生成 |
| 承诺化 | `private` + 权重哈希作公开输入 | 电路不变，只换一个 instance；**推荐** |
| 混合 | 结构用 ZK 证，权重用签名/哈希证 | 弱化「推理完整性」，但工程最轻 |

**推荐第二条**：权重走 `private`，把 `H(weights)` 作为公开输入。这样 vk 只绑结构，每轮只换一个 32 字节的哈希。验证方检查「这个哈希等于本轮聚合结果的哈希」，就同时满足了两个需求。

## 五、一个容易漏掉的细节

`hashed` 可见性在 EZKL 里是**逐张量**设的，不是全局开关。

也就是说，你可以让第一层权重 `fixed`、后面几层 `private`。这在「部分层固定、部分层可换」的场景有用，但会让配置复杂度上升，也容易配错。

**实践建议**：先用全局配置跑通，再考虑逐张量。

## 六、自检答案

> 问：说清「联邦学习每轮都换全局模型时该选哪个」，以及两种选择的代价。

答：选 `private`（配一个权重哈希作为公开输入），或 `hashed`。`fixed` 不能用，因为权重进了 fixed 列，vk 绑定它，每轮换模型都要重新 compile + setup 并重新生成 265 MB 的 pk。`private` 的代价是 vk 只绑结构，必须靠外部机制（哈希、签名）补上「用的是哪一版权重」；`fixed` 的代价是每轮重建，工程上不可行。

## 七、一句话记住

**fixed = 把模型照片印在身份证上；private = 身份证上写「另附照片」。前者防掉包，后者能换人。**
