# compile约束系统固化

> **核心** ｜ 前置：03_算术化/02_PLONKish/01_三类列

**一句话**：把 ONNX 图变成固定列写死的电路；结构定死之后才能生成密钥，也才能算出需要多少行。

**打个比方**：把菜谱定死成一条流水线。流水线一装好，换一道菜就得重新装一遍——这就是「换模型要重跑 compile+setup」。

**在 EZKL 里的落点**：model.compiled；compile-circuit 命令。

> 读完约 7 分钟。这一篇解释一个让很多人意外的数字：compile 只要 0.03 秒。

## 一、compile 在干什么

输入：`model.onnx` + `settings.json`
输出：`model.compiled`（66 KB）

它做的事只有三件：

1. **按 settings 分配行**：算出每个算子要占哪几行、哪几列；
2. **算出所有 fixed 列的值**：选择子、常量、查找表内容；
3. **记下所有约束的布局**：哪个门在第几行、连到哪几条线。

**没有密码学运算。** 没有承诺、没有 NTT、没有 SRS。所以它快 —— 本次实测端到端 0.03 秒，比读文件还快。

## 二、为什么它必须「冻住」

因为 fixed 列一旦确定，vk 就绑定了它。

- 权重进 fixed 时，vk 绑定的是「这份权重」；
- 选择子进 fixed 时，vk 绑定的是「这个运算布局」；
- 查找表进 fixed 时，vk 绑定的是「这张表的内容」。

所以 compile 的产物不是「中间结果」，而是**电路的定义本身**。改一个常量，电路就变了，vk 就作废。

## 三、一条完整的因果链

```
改模型结构 / 改 settings
   ↓
compile 产物变 → vk 变
   ↓
旧 proof 全部失效，必须重新 setup
   ↓
pk（265 MB）重新生成
```

这就是为什么「联邦学习每轮换全局模型」在默认配置下走不通（`04/03/05`）：每轮都要重跑后面三步。

## 四、一个反直觉的点

`model.compiled` 只有 66 KB，而 `pk.key` 有 265 MB。

为什么？因为 compiled 只描述「结构」，不含任何密码学材料；pk 是「把这个结构代进 SRS 之后算出来的一堆预计算结果」。

**结构是小的，密码学是大的。** 这个比例在整棵树里反复出现。

## 五、compile 会失败吗

会，而且失败信息通常不友好。常见原因：

- 某个 ONNX 算子不被支持（先用 `ezkl table` 查）；
- `settings.json` 里的 `num_rows` 估小了，约束装不下；
- 输入形状对不上（reshape 链断了）。

**实践建议**：先用小模型跑通整条链，再换大模型。compile 失败时，问题 90% 在算子和形状，不在密码学。

## 六、自检答案

> 问：说清「编译后改模型为什么要重来一遍」。

答：因为 compile 把模型翻译成了固定的约束布局：每个算子占哪几行、每个选择子取什么值、查找表内容是什么，全部写进 fixed 列。而 vk 是对整个电路（含 fixed 列）的绑定，fixed 一变，vk 就失效，必须重新 compile → setup → 重新生成 pk。改模型本质上就是改电路，所以没有「增量编译」这回事。

## 七、一句话记住

**compile 不编译机器码，它编译「约束布局」。布局一改，钥匙全换。**
