# 证明生成全流程

> **核心** ｜ 前置：03_算术化/02_PLONKish/05_商多项式与恒等式检验、02_承诺与哈希/02_承诺方案/03_KZG多项式承诺

**一句话**：承诺 witness → 取挑战 → 算商多项式 → 多开点归约 → 输出 proof。五步，一步都不能省。

## 一、先给结论

一个 Halo2 证明分五个阶段：

| 阶段 | 干什么 | 相对耗时 |
|---|---|---|
| 1. commit | 对每一列 advice 做 KZG 承诺 | 高（MSM） |
| 2. squeeze | 从 transcript 取挑战 β、γ、α | 可忽略 |
| 3. quotient | 算商多项式 t(X) 并承诺 | **最高**（NTT + 除法） |
| 4. evaluate | 在随机点 `x`（论文记作 ζ）求值所有多项式 | 中 |
| 5. multiopen | 把所有开值合成一个 KZG 证明 | 中（MSM + 配对准备） |

## 二、逐段说

**阶段 1：承诺**

把每一列的值（比如 a 列 65536 个数）插值成多项式，再算 `p(τ)·G`。

这一步的核心运算是 **MSM**（多标量乘加）：65536 个「标量 × 点」再求和。它是并行的，也是 GPU 加速唯一能帮上忙的地方（`06/02/03`）。

**阶段 2：取挑战**

把上一阶段的承诺 absorb 进 transcript，按 halo2 的顺序挤挑战：**theta**（查表线性化）→ **beta、gamma**（置换论证）→ **y**（门约束线性化）→ **x**（求值点）。注意论文里的 α、ζ 在 halo2 代码里不存在，对应的是 y 和 x。

这一步本身不耗时，但它是**安全性的枢纽**：挑战必须依赖此前的所有承诺（`02/01/04`）。

**阶段 3：算商多项式**

这是最重的一步。要做：

1. 把门约束、置换约束、查找约束全部组合成一个 G(X)（用 α 加权）；
2. 除以 Z_H(X) = Xⁿ − 1；
3. 对结果 t(X) 再做承诺。

多项式除法在系数表示下很贵，实际要先做 NTT 转到点值表示，除法变成逐点相除，再 NTT 转回来。**两次 NTT + 一次逐点除**，这就是那几秒的去向。

**阶段 4：求值**

取一个新的随机点（halo2 里叫 `x`，论文记作 ζ；也来自 transcript），把所有多项式在该点求值：a(x)、b(x)、t(x)…

求值本身是 O(n) 的，但它产生了一堆「需要被打开」的值 —— 这就是下一阶段的问题。

**阶段 5：多开点**

十几个多项式、好几个点，如果逐个开，proof 会变成十几个点。所以要用随机系数揉成一个（`04/02/02`），再一次 KZG 打开。

最终产出 `proof.json`，19 KB。

## 三、时间去哪了

按本项目的实测（3 万多行，prove 2.9–4.2 秒）粗分：

- MSM（承诺 + 多开点）：约一半；
- NTT + 商多项式：约三分之一；
- 序列化、哈希、杂项：剩下的一点。

**模型的计算本身几乎不占时间** —— 它在 `gen-witness` 阶段就做完了（0.16 秒）。所以「证明慢」和「模型慢」是两件完全无关的事。

## 四、在 EZKL 里

- 入口在 `src/pfsys`，最终调 halo2 的 `create_proof`；
- 中间产物不落盘（除了最后的 proof），所以中途失败只能重跑；
- `pk.key`（265 MB）在这一步被读进内存 —— 这也是为什么 prove 的峰值内存远大于模型本身。

## 五、一个容易误解的地方

「prove 慢是因为模型大」—— 不准确。

准确说法：**prove 慢是因为电路行数多**。而行数由模型结构 + 量化精度 + 查找表大小共同决定（`03/01/02`）。

同样的模型，把 `lookup_range` 从 ±128 加宽到 ±2048（表从 256 行涨到 4096 行），prove 可能慢一截 —— 模型一个参数没变。

## 六、自检答案

> 问：按顺序说出 prove 的五个阶段，并指出哪一步最耗时。

答：commit（承诺各列）→ squeeze（取挑战）→ quotient（算商多项式并承诺）→ evaluate（在 x/ζ 求值）→ multiopen（合并开值）。最耗时的是 quotient，因为它要把所有约束组合成 G(X) 再做多项式除法，需要两轮 NTT；其次是 commit 与 multiopen 里的 MSM。

## 七、一句话记住

**prove 不是在算模型，是在跟多项式打交道。模型算得快不快，跟证明快不快没关系。**
