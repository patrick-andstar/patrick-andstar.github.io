> 读完约 7 分钟。这一篇讲 Groth16 用的约束系统，对照着看能明白 PLONKish 改进了什么。

## 一、形式

R1CS = Rank-1 Constraint System。

每一条约束长这样：

> **(A·z) ∘ (B·z) = C·z**

- z 是「见证向量」：`[1, 公开输入, 私密输入]`；
- A、B、C 是系数向量；
- ∘ 是逐元素乘。

翻译成人话：**左边两个线性组合相乘，等于右边一个线性组合。**

注意「Rank-1」的意思：每条约束里只有**一次乘法**。

## 二、举个具体的

约束 `z₁ · z₂ = z₃`：

- A = [0,1,0,0,…]（挑出 z₁）
- B = [0,0,1,0,…]（挑出 z₂）
- C = [0,0,0,1,…]（挑出 z₃）

于是 `(A·z)(B·z) = z₁·z₂ = z₃ = C·z` ✓

再看一个加法 `z₁ + z₂ = z₃`：

- 可以写成 `(z₁ + z₂) · 1 = z₃`
- A = [0,1,1,0,…]，B = [1,0,0,0,…]（挑出常数 1），C = [0,0,0,1,…]

## 三、和 PLONKish 的差别

| | R1CS | PLONKish |
|---|---|---|
| 一条约束能做几次乘法 | **1 次** | 多次（自定义门） |
| 结构 | 一堆独立的约束 | 一张表格（有行有列） |
| 复制约束 | 靠变量编号（天然共享） | 靠置换论证 |
| 主要用户 | Groth16、Spartan | PLONK、Halo2 |
| 证明大小 | 极小（Groth16 ~200 B） | 小（KZG ~33 B/点） |
| 可信设置 | 每个电路一次 | 一份通用 SRS |

**最关键的一行是第一行**：R1CS 每条只能一次乘法，所以一个 `a·b·c` 要拆成两条约束；PLONKish 的自定义门可以一次算完。

## 四、R1CS 的优点：变量天然共享

在 R1CS 里，「同一个变量出现在多条约束里」是免费的 —— 因为大家引用的都是 z 的同一个下标。

PLONKish 不行：表格是按位置组织的，同一个值出现在不同格子，必须靠**复制约束 + 置换论证**来绑定（`03/02/03`）。

所以：

- R1CS 在「复用多」的场景更自然；
- PLONKish 在「批处理、查找表」的场景更强。

## 五、为什么 EZKL 不用 R1CS

三个原因：

1. **查找表**：zkML 的非线性算子全靠查表，R1CS 对查找表支持很差；
2. **自定义门**：卷积/曲线运算需要多次乘法，R1CS 要拆很多条；
3. **通用 SRS**：Groth16 每个电路都要重新做可信设置，模型一换就废。

第 3 条对 zkML 是致命的：你不可能为每个模型做一次仪式。

## 六、自检答案

> 问：一句话说出 R1CS 与 PLONKish 的主要差别。

答：R1CS 每条约束只允许一次乘法（形如 (A·z)∘(B·z)=C·z），靠变量下标天然共享；PLONKish 把约束组织成表格，允许自定义门做多次乘法，用置换论证实现「同一值出现在不同格子」。前者适合 Groth16（proof 极小但每电路一次可信设置），后者适合 Halo2（通用 SRS + 查找表 + 自定义门）。

## 七、一句话记住

**R1CS 一条一次乘法、靠下标共享；PLONKish 一张表、靠置换绑定。后者为查找表和自定义门而生。**
