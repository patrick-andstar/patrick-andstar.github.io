# 商多项式与恒等式检验

> **核心** ｜ 前置：01_数学地基/04_多项式/03_多项式恒等式与Schwartz-Zippel

**一句话**：「所有门约束在整域上都成立」等价于「这些约束之和能被 Z_H(X) 整除」，商多项式的次数就是证据。

**打个比方**：把「每条检查都必须等于零」加成一个总式子，再看它能不能被一个固定式子整除。能整除，就说明每条都成立。

**在 EZKL 里的落点**：halo2 的 quotient polynomial；不在 ezkl 源码，在底层库。

## 一、问题

现在你有一张表，每一行都有一条约束（`q_L·a + q_R·b + …`）。65536 行，就是 65536 个「必须等于零」的式子。

验证者要确认：**每一行都等于零。**

逐行验？65536 次，比重新算一遍还慢。

## 二、第一步：把「行」变成「多项式」

上一篇（`01/04/01`）说过：行就是点。

- 第 i 行对应 x = ωⁱ（ω 是 n 次单位根，n = 65536）；
- 把每一列的值插值成多项式：a(X)、b(X)、c(X)；
- 选择子也插值成多项式：q_L(X)、q_R(X)…

于是「第 i 行的门约束等于零」就变成：

> 对每个 i，`q_L(ωⁱ)·a(ωⁱ) + … = 0`

把这整串记作一个多项式 **G(X)**：

> G(X) = q_L(X)a(X) + q_R(X)b(X) + q_M(X)a(X)b(X) + q_O(X)c(X) + q_C(X)

**注意 G 不是一个简单多项式**：它是好几个多项式的乘积与和。次数会比单个高，但仍然是多项式。

## 三、第二步：把「n 个点为零」变成一个整除

定义「在 n 个单位根上为零」的那个多项式：

> Z_H(X) = Xⁿ − 1

它的根恰好就是 ω⁰, ω¹, …, ω^(n−1)。所以：

> **G(ωⁱ) = 0 对所有 i** ⟺ **Z_H(X) 整除 G(X)**

这就是多项式余数定理的直接应用：如果 G 在所有根上都为零，那它含有 Z_H 这个因式。

于是定义**商多项式**：

> h(X) = G(X) / Z_H(X)　（论文里常写作 t(X)）

如果每一行约束都成立，h 是一个正常的多项式（次数 = deg G − n）。如果某一行不成立，除法就除不尽，h 不存在。

（记号：论文常写 t(X)，halo2 代码里叫 `h(X)`。下面统一用 h。）

### 3.1 多种门怎么合并：用 y 的幂加权

一个电路里往往有好几类约束（算术门、查找、置换、自定义门），次数各不相同。**不能直接相加**——低次项会被高次项淹没，攻击者可以借机抵消。

halo2 取一个随机挑战 **y**，按幂次加权：

> G_y(X) = Σᵢ yⁱ · G_i(X)

只要有一个 G_i 在某行不为零，加权和几乎不可能恰好为零。这就是 vanishing argument 里那个 `ChallengeY` 的用途。

### 3.2 h 不是一个多项式，是好几段

G 的次数可能高于 n（门的最高次数 × 行数），所以 h 的次数也会超过 n。

halo2 把 h 按 n 切段：

> h(X) = h₀(X) + Xⁿ·h₁(X) + X²ⁿ·h₂(X) + …

每段次数 < n，各自承诺成一个点。所以 proof 里有**好几个商多项式承诺**（本项目量级 3–4 个），不是「一个 t」。

## 四、第三步：验证者自己算 h(x)，只查一个点

注意和「朴素版本」的区别：验证者**不是**向证明者索要 G(r) 和 h(r)，而是：

1. 从 proof 读出各多项式在随机点 x 的求值（a(x)、b(x)、选择子…，这些是开值）；
2. 用这些值现场算出每条约束表达式的值 exprᵢ(x)；
3. 按 y 的幂加权求和：Σ yⁱ·exprᵢ(x)；
4. 除以 (xⁿ − 1)，得到 h(x) 的**期望值**；
5. 与证明者开出的 h(x) 比较（通过 KZG 打开）。

一次比较，就完成了「65536 行全都成立」的验证。

## 五、为什么这不算偷懒

因为 x 是随机且不可预测的：

- 如果 G 真的能被 Z_H 整除，等式在**任何** x 上都成立；
- 如果除不尽（某一行错了），那 G − Z_H·h 是一个非零多项式，最多在少数点上碰巧为零，随机撞上的概率 ≤ 次数/|F|，小到 2⁻²⁰⁰ 量级。

所以「验一个点」不是近似，是**概率意义上的等价**。

## 六、在 EZKL 里

- 商多项式由 halo2 的 vanishing 模块处理，不在 ezkl 仓库内；
- 它是 prove 阶段最耗时的部分之一（多项式除法 + NTT）；
- `proof.json` 里存的是 **h 各段的承诺 + h(x) 的求值**，不是整个 h。

这也解释了一个现象：**prove 的时间主要花在「算 h」上，而不是「算模型」上**。模型的计算在生成 witness 时就算完了（那一步只要 0.16 秒），剩下的几秒全在跟多项式打交道。

## 七、自检答案

> 问：用三句话解释 quotient polynomial 到底在证什么。

答：第一，把所有约束在每一行的取值插值成一个多项式 G(X)；第二，G 在所有单位根上为零，等价于 G 能被 Z_H(X) = Xⁿ − 1 整除；第三，于是「每行都成立」变成「存在一个多项式 h 使 G = Z_H·h」，而验证者不必看 G 或 h，只要用它从 proof 里读到的那些开值算出 Σyⁱ·exprᵢ(x)，除以 (xⁿ−1)，再和证明者开出的 h(x) 比一次。

## 八、一句话记住

**「每行都为零」= 「能被 Xⁿ−1 整除」。一次除法，替掉六万次检查。**
