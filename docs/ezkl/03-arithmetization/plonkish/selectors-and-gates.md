# 选择子与门约束

> **核心** ｜ 前置：03_算术化/02_PLONKish/01_三类列

**一句话**：用选择子（0/1）开关，让同一组列在不同行执行不同运算，一个通用门搞定所有算术。

**打个比方**：同一张表格，用一排 0/1 开关决定这一行是做加法还是做乘法——不用为每种运算单独准备纸。

**在 EZKL 里的落点**：src/circuit/table.rs 的 SelectorConstructor。

!!! question "自检（能答上来就算过）"
    写出一个受选择子 s 控制的通用门表达式。

---

> 读完约 8 分钟。这一篇给你 PLONK 的那条核心公式，不背也行，但要能读懂。

## 一、问题

一张表要执行很多种运算：加法、乘法、混合、常量赋值……

难道每种运算都准备一套列？那列数会爆炸（列越多，承诺越多，证明越大）。

解法：**用一套通用列，靠「开关」决定这一行算什么。**

## 二、通用门公式

PLONK 的核心就这一条：

> **q_L·a + q_R·b + q_M·a·b + q_O·c + q_C = 0**

五个 q 就是五个**选择子（selector）**，都是 0 或 1（q_C 是常数，可以是别的值）。a、b、c 是这一行三个 advice 单元格的值。

看它怎么变出不同运算：

| 想要 | q_L | q_R | q_M | q_O | q_C | 等式变成 |
|---|---|---|---|---|---|---|
| 加法 c = a+b | 1 | 1 | 0 | −1 | 0 | a + b − c = 0 |
| 乘法 c = a·b | 0 | 0 | 1 | −1 | 0 | a·b − c = 0 |
| 常量 c = 7 | 0 | 0 | 0 | −1 | 7 | 7 − c = 0 |
| 布尔约束 a∈{0,1} | 1 | −1 | 0 | 0 | 0 | a − a² … 见下 |

（最后一行要写成 `a·a − a = 0`，所以是 q_M = 1、q_L = −1、q_O = 0。）

## 三、算一个具体的

取 a = 3、b = 4、c = 7，开加法模式（q_L=q_R=1, q_O=−1）：

> 1×3 + 1×4 + 0×(3×4) + (−1)×7 + 0 = 3 + 4 − 7 = **0** ✓

改成乘法模式（q_M=1, q_O=−1），同时把 c 改成 12：

> 0 + 0 + 1×(3×4) + (−1)×12 = 12 − 12 = **0** ✓

如果 c 还是 7：

> 12 − 7 = **5 ≠ 0** → 约束不成立，证明失败。

这就是「约束」的样子：**不是 if 判断，是一个必须等于零的式子。**

## 四、关键：选择子是常量，不是运行时开关

这一点极易误解。

`q_L` 这些值是 **fixed 列**里的常量，在 `compile` 时就写死了（`03/02/01`）。所以：

- 它们不是「程序里的 if」，而是「表格上印好的运算类型」；
- 整个电路每一行算什么，编译后就定了；
- 换一种运算组合 = 换一张表 = 重新 compile。

这也解释了一个常见困惑：「为什么 EZKL 换个模型要重新编译？」因为门的选择子布局变了。

## 五、为什么叫 PLONKish 而不是 PLONK

- **PLONK**（2019）：只有上面那一种门，所有运算都得往这个模子里塞；
- **PLONKish**（halo2 的叫法）：允许**自定义门**（custom gate），你可以定义 `q_1·a²·b + q_2·c = 0` 这种更复杂的式子，一个门吃掉更多行。

EZKL 两者都用：普通算术走通用门，椭圆曲线运算、矩阵乘这些走自定义门（`03/02/04`）。

## 六、在 EZKL 里

- `src/circuit/table.rs` 的 `SelectorConstructor`，负责在编译期为每一行算出该开哪个选择子；
- 选择子的取值最终进入 fixed 列，由 vk 绑定；
- 所以**改选择子 = 改电路 = 换 vk**。

## 七、自检答案

> 问：写出一个受选择子 s 控制的通用门表达式。

答：把两个运算都写进一个式子，用 s 当开关：`s·(a·b − c) + (1−s)·(a + b − c) = 0`。s=1 时退化成乘法约束，s=0 时退化成加法约束。s 本身是 fixed 列的常量。这就是「选择子」这个名字的来源——它在选，但选的结果在编译期就定了。

## 八、一句话记住

**一个通用门 + 五个 0/1 开关 = 所有算术。开关是常量，编译后不可改。**
