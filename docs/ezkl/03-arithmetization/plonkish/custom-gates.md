# 自定义门

> **支撑** ｜ 前置：03_算术化/02_PLONKish/02_选择子与门约束

**一句话**：把常用的小运算（如椭圆曲线加、椭圆曲线倍）打包成一个门，一次吃掉多行。

**打个比方**：把「一次椭圆曲线加法」这种常做的小动作，做成一个专用模具，一次压出好几个格子，省行。

**在 EZKL 里的落点**：halo2 的 ConstraintSystem::create_gate；ecc chip 大量使用。

## 一、标准门的局限

PLONK 的通用门只能表达：

> q_L·a + q_R·b + q_M·a·b + q_O·c + q_C = 0

它只有**一次乘法**（a·b）。

但很多运算需要多次乘法：

- 椭圆曲线点加：λ = (y₂−y₁)/(x₂−x₁)，然后 x₃ = λ²−x₁−x₂ —— 至少两次乘；
- 矩阵乘的一个元素：Σ aᵢbᵢ —— 多次乘加；
- 哈希的一轮：S-box（五次方）+ MDS 混合 —— 多次乘。

如果只用标准门，每个乘法都要拆成一行。**点加要 5 行，哈希一轮要 10 行。**

## 二、自定义门能做什么

halo2 允许你定义任意形式的约束：

> f(a, b, c, d, …, q₁, q₂, …) = 0

其中 `f` 可以是**任意次数的多项式**，只要次数不太高。

比如定义一个「曲线加点」门：

> q₁·(λ·(x₂−x₁) − (y₂−y₁)) + q₂·(x₃ − λ² + x₁ + x₂) = 0

两次乘法、一次除法（用辅助变量表示），一个门搞定。

## 三、代价一：约束的次数（degree）

这是最不直观的一点。

- 标准门是 degree 2（因为有 a·b）；
- 自定义门可以是 degree 3、5、甚至更高。

而整个证明系统的安全性、以及商多项式的次数，都跟**最大 degree** 有关：

- degree 越高，商多项式越大，proof 里要多存几段；
- 而且 halo2 有个「degree bound」：电路的总约束次数不能超过某个上限（通常是 9 左右）。

所以**自定义门不是免费的**：你省了行数，但每行的「重量」增加了。

## 四、代价二：布局更复杂

自定义门要占更多的列（因为参数多）。

- 标准门：3 个 advice 列就够；
- 曲线门：可能要 6–9 个 advice 列。

列数增加 → 每列的承诺增加 → 证明变大。

所以真实系统里是「按需开自定义门」：用在真正高频且省行明显的运算上（曲线、哈希），别滥用。

## 五、在 EZKL 里（已核对源码，纠正两处）

先纠正一个想当然的说法：**EZKL 的电路里没有椭圆曲线运算**。

曲线运算发生在承诺、多开点、验证这些「电路外」的环节；电路内部只有域上的加乘、查表和置换。所以 `halo2_wrong_ecc` 虽然出现在 `Cargo.toml` 里，但 `src/` 里搜不到任何直接调用 —— 它是 `snark-verifier` 带进来的传递依赖（用于验证器电路，本项目用不到）。

EZKL 真正用自定义门的地方是：

| 位置 | 用什么门 |
|---|---|
| `src/circuit/ops/chip.rs` | 逐算子的门（含范围检查专用门） |
| `src/circuit/ops/chip/einsum/mod.rs` | 矩阵乘/张量收缩的 init 与 acc 两类门 |
| `src/circuit/modules/poseidon.rs` | S-box（五次方）走 `halo2_gadgets` 的 `Pow5Chip` |

**一个可观察的现象**：卷积多 → einsum 的自定义门用得多；只是全连接 + ReLU → 标准门就够。

## 六、一个容易误解的点

「自定义门 = 更高级的优化」——不一定。

如果某个运算只出现几次，用自定义门反而亏：你为它开了几列，但只用了几行。

**判断标准**：出现次数 × 每次省下的行数 > 新增列数 × 总行数。

粗略地：**高频才值得自定义**。

## 七、自检答案

> 问：举一个用自定义门省掉 3 行的具体例子。

答：拿 halo2 生态里最典型的例子说（注意这不是 EZKL 的用法）：椭圆曲线点加。用标准门要拆成「算 λ、算 λ²、算 x₃、算 y₃」至少 5 行；用一个自定义门可以直接写 `λ(x₂−x₁) = y₂−y₁` 和 `x₃ = λ²−x₁−x₂` 两条约束在一行里，省下 3–4 行，代价是 degree 升到 3、且要占 6 个 advice 列。EZKL 自己用自定义门的地方是 einsum 的 init/acc 门（`ops/chip/einsum/mod.rs`），思路相同：把一次矩阵乘的「初始化」和「累加」各做成一个门。

## 八、一句话记住

**自定义门 = 一行干多行的活。省行数，但加 degree、加列数，只对高频运算划算。**
