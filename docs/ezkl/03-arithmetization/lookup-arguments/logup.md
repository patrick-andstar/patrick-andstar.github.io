# LogUp与对数导数

> **支撑** ｜ 前置：03_算术化/03_查找表/02_Plookup原理

**一句话**：用 1/(x−t) 这类项的对数导数，把成员关系压成一个求和等式，比 Plookup 更省 proof 空间。

**打个比方**：把「在不在表里」换成「一批倒数加起来对不对」，像用总重量核对两筐苹果——不用逐个数。

**在 EZKL 里的落点**：zkonduit 分支的 mv-lookup 特性即此路线。

## 一、Plookup 的痛点

Plookup 要构造「排序合并序列」，这需要预先算一个排列，还要两次 grand product。

问题：

- 预处理成本高；
- 表大了之后，排列的构造很麻烦；
- 多列查询要拆成多次。

LogUp（2022）换了个思路：**根本不需要排序。**

## 二、核心恒等式

先看一个简单的观察。

假设表 t = {2, 3, 5}，查询 f = {2, 2, 5}（2 出现两次）。

取一个随机数 c（不等于任何表元素），考虑：

> Σ_{x∈f} 1/(x − c)  vs  Σ_{y∈t} m_y/(y − c)

其中 m_y 是 y 在 f 里出现的次数（这里 m₂=2, m₃=0, m₅=1）。

如果 f ⊆ t，两个和**必然相等**：

> 1/(2−c) + 1/(2−c) + 1/(5−c) = 2/(2−c) + 0/(3−c) + 1/(5−c) ✓

反过来，如果 f 里有一个不在 t 里的元素（比如 7），那左边会多出一项 1/(7−c)，右边没有，等式不成立（除非 c 恰好等于 7，概率极低）。

**这就是全部原理：用「倒数之和」代替「集合包含」。**

## 三、为什么叫「对数导数」

数学上有个恒等式：

> d/dx log(∏(x − aᵢ)) = Σ 1/(x − aᵢ)

也就是说，「连乘的对数导数」等于「倒数和」。

Plookup 用的是连乘（grand product），LogUp 用的是它的对数导数形式 —— 名字由此而来。

好处：**连乘需要累积乘积（数值会爆），倒数和只需要加法累积**，在有限域里更稳定、更省约束。

## 四、怎么在电路里实现

要算 Σ 1/(x − c)，需要每个元素做一次**域除法**。

而电路里除法很贵（`05/03/02`）。所以实际实现用**批量求逆**技巧：

1. 先把所有 (x − c) 连乘，得到 P；
2. 用一次求逆算出 1/P；
3. 再回推每个 1/(x − c)。

这样 N 次除法变成 **1 次求逆 + 3N 次乘法**，快得多。

## 五、代价与边界

| 项 | LogUp |
|---|---|
| 需要排序 | 不需要 |
| 约束数 | 比 Plookup 少（约一半） |
| 预处理 | 只需算重数 m_y |
| 风险 | **分母为零**：若 f 里有元素等于 c，除法失败 |

最后一条是 LogUp 的软肋：随机 c 必须避开所有查询值。实践中：

- c 由 transcript 给出，攻击者无法预知；
- 若真撞上，证明者可以换一个 c（但要防止他反复试）；
- 实现上通常用「c 取自更大的域」来把概率压到可忽略。

## 六、在 EZKL 里

Cargo.toml 里 `halo2_proofs` 开了 `mv-lookup` 特性 —— 这是 zkonduit 分支对查找论证的扩展（`03/03/04`）。

LogUp 的思想在里面：用累积和而不是累积积，用一次批量求逆代替 N 次除法。

**你能观察到的现象**：启动 prove 时日志里会出现 lookup 相关的行数统计，那部分就是查找论证占的配额。

## 七、自检答案

> 问：说清 LogUp 里那个求和等式为什么成立。

答：因为若 f ⊆ t，则对每个表元素 y，f 中出现 y 的次数是 m_y，两边按 y 分组后完全一致：Σ_{x∈f} 1/(x−c) = Σ_y m_y/(y−c)。这是「按值分组计数」的解析表达。若 f 含表外元素，左边会多出无法与右边抵消的项，除非随机 c 恰好等于该元素（概率可忽略）。

## 八、一句话记住

**Plookup 靠排序，LogUp 靠倒数和。一个乘法累积，一个加法累积，后者更省。**
