## 一、一句话说清

> **用了 KZG，你就默认相信：生成 SRS 的那场仪式里，至少有一个人真的删掉了自己的秘密。**

这不是 EZKL 特有的，是所有基于 KZG 的系统（包括以太坊的 blob）共同的前提。

## 二、为什么删不掉就完蛋

SRS 里的每个点都是 `τⁱ·G`。如果某人知道 τ：

1. 他可以算出任意多项式在 τ 处的值；
2. 于是可以为**任意**陈述伪造承诺和打开证明；
3. 验证方看不出任何异常 —— 所有等式都成立。

**这是「静默失效」：系统看起来完全正常，实际上已经没有任何安全性。**

## 三、仪式怎么把风险摊薄

多人依次参与，每人乘上自己的随机数 sᵢ：

> τ = s₁ · s₂ · … · sₙ

只要有一人删除自己的 sᵢ，就没人能算出 τ（因为需要全部 sᵢ）。

以太坊的 KZG 仪式有十几万人参与，就是靠这个「至少一个诚实」的假设把风险压到极低。

## 四、工程上你必须做的三件事

**第一，用官方来源。**

EZKL 的 SRS 从 `kzg.ezkl.xyz` 下载。别从论坛、网盘、别人给的压缩包里拿。

**第二，校验哈希。**

`src/srs_sha.rs` 提供了校验能力。下载后第一件事就是比对 SHA256。**不校验等于把地基交给任何人。**

**第三，锁定版本。**

不同来源的 SRS 可能格式相同但内容不同（比如不同的仪式）。混用会让 setup 和 prove 用不同的参数，结果就是验证失败——或者更糟，你不知道为什么失败。

## 五、如果他真留了 τ，你能发现吗

**很难。**

- 单个证明看不出问题；
- 只有在「同一个陈述出现两个互相矛盾的合法证明」时才会暴露；
- 而在那之前，攻击者可以安静地伪造任何东西。

所以这件事**不能靠事后检测，只能靠事前选择**。这也是为什么「SRS 来源不明」被列进攻击面（`06/04/03`）。

## 六、有没有不用可信设置的选项

有，但都有代价：

| 方案 | 免可信设置 | 代价 |
|---|---|---|
| STARK / FRI | 是 | proof 大（几十 KB 到几百 KB） |
| Halo2 + IPA | 是 | proof 随电路对数增长（v23 已删） |
| Bulletproofs | 是 | 验证慢、生态小 |
| **KZG** | **否** | **proof 小、验证快** |

所以这是一个明确的交换：**你要小 proof 和快验证，就得接受一次性的信任。**

## 七、写报告时怎么说

不要写「本系统无需信任第三方」——用了 KZG 就不是。

正确表述：

> 本系统采用 KZG 多项式承诺，安全性依赖可信设置仪式（至少一名参与者诚实）与 SRS 文件的完整性校验（SHA256）。若需完全免除该假设，可替换为基于 FRI 的证明系统，代价是证明体积增大一个数量级。

这句话既诚实，又给出了备选方案，评审很难挑。

## 八、自检答案

> 问：说清「如果 SRS 是别人生成的，你在信任谁」，以及怎么验证它。

答：你在信任「生成者已经销毁 τ」以及「你拿到的文件确实是那场仪式的产物」。前者无法验证，只能靠仪式的多方参与把风险摊薄到「至少一人诚实」；后者可以通过 SHA256 校验文件哈希、并核对官方公布的哈希值来验证。两条都不做，等于把系统安全性交给一个陌生人。

## 九、一句话记住

**KZG 的安全不靠数学，靠「有人把秘密删了」。你只能选来源、校哈希，然后接受它。**
