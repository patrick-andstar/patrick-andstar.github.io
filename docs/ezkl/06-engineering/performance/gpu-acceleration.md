## 一、prove 的时间构成

回忆 `04/02/01`：

| 阶段 | 主要运算 | 能 GPU 吗 |
|---|---|---|
| commit | **MSM** | **能，接近线性加速** |
| quotient | NTT + 多项式除法 | 能，但收益较小 |
| evaluate | 求值 | 不能（量太小） |
| multiopen | MSM | 能 |

**MSM 占大头**，而 MSM 恰好是 GPU 最擅长的：几千个独立的「标量 × 点」，天然并行。

## 二、icicle 是什么

INGONYAMA 开发的 GPU/加速器库，提供 MSM、NTT 的 CUDA 实现。

EZKL 通过 feature flag 接入：

```toml
icicle-runtime = { git = ".../ingonyama-zk/icicle", optional = true }
```

仓库根目录有 `setup-gpu.sh`，说明这是「可选路径」，不是默认。

## 三、加速比（量级）

公开数据和社区报告的量级：

| 运算 | CPU（32 线程） | GPU（中端） | 加速 |
|---|---|---|---|
| MSM（k=20） | 10 s | 0.5–1 s | 10–20× |
| NTT（k=20） | 5 s | 1–2 s | 2–5× |
| 整体 prove | 40 s | 5–10 s | 4–8× |

**注意最后一行**：整体加速远小于 MSM 的加速，因为有串行部分（置换、查找的累积）拖后腿。

## 四、三个限制

**限制一：只有 MSM/NTT 能加速。**
序列化、哈希、累积递推都是串行的，GPU 帮不上。

**限制二：显存是瓶颈。**
k=20 时中间数据约 10 GB，中端显卡（8–12 GB）装不下。要么分块，要么上大显存卡。

**限制三：编译与部署成本。**
要装 CUDA、编译 icicle 后端、处理驱动兼容。对于一个「跑一次实验」的项目，这部分成本可能超过收益。

## 五、什么时候值得上 GPU

| 场景 | 建议 |
|---|---|
| 只跑几个小模型验证可行性 | **不值**，CPU 够了 |
| 要反复调参（calibrate 多次） | 值，因为 calibrate 也吃算力 |
| 生产环境持续出证明 | 值，摊薄固定成本 |
| 一次性的论文实验 | 看时间预算，通常不值 |

## 六、一个容易忽略的点

**verify 不需要 GPU。**

验证只要毫秒级，瓶颈是进程启动和 vk 反序列化（`06/01/02`），不是算力。

所以「上 GPU 让验证变快」是错的。GPU 只影响**证明侧**。

## 七、自检答案

> 问：说清「GPU 加速的是哪一步、哪一步加速不了」。

答：加速的是 MSM（承诺与多开点里的多标量乘）和 NTT（商多项式计算），因为它们是大量独立运算、天然并行。加速不了的是：串行的累积递推（置换论证、查找论证的 grand product / 累积和）、序列化与哈希、以及验证侧（本来就毫秒级）。所以整体加速通常只有 4–8 倍，远小于 MSM 单项的 10–20 倍。

## 八、一句话记住

**GPU 只加速 MSM 和 NTT。串行累积、序列化、验证，一样都帮不上。**
