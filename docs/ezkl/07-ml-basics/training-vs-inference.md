# 推理与训练的区别

> **核心** ｜ 前置：07_机器学习预备/01_神经网络就是矩阵乘加

**一句话**：推理只做前向：输入进、结果出。训练还要反向传播算梯度、再用优化器改权重，中间状态多得惊人。

**在 EZKL 里的落点**：05/04/04 的结论就建立在这条上：ZK 只证前向。

## 一、推理：一次前向

```
输入 x
 → 第 1 层：h₁ = f₁(x)
 → 第 2 层：h₂ = f₂(h₁)
 → …
 → 输出 y = fₙ(hₙ₋₁)
```

没有循环、没有状态、没有随机性（推理模式下 dropout 关闭）。

**给定输入和权重，输出完全确定。** 这正是电路需要的性质：确定性、静态、可复现。

## 二、训练：三步循环

```
for 每个 batch:
    1. 前向：算出 y_pred
    2. 算损失：L = loss(y_pred, y_true)
    3. 反向：从 L 往回算每层的梯度 ∂L/∂w
    4. 更新：w ← w − lr · ∂L/∂w
```

关键在第 3 步：**反向传播**。

它用链式法则，从最后一层往前，逐层算「损失对每个参数的偏导」。要算这个，必须**保存前向时每一层的中间激活值** —— 这就是「中间状态爆炸」的来源（`05/04/04`）。

## 三、一个数量对比

假设网络有 L 层、每层计算量 C：

| 阶段 | 计算量 | 需要保存的中间状态 |
|---|---|---|
| 前向 | L·C | L 层的激活（反向要用） |
| 反向 | 约 2L·C | 每层的梯度 |
| 更新 | 参数量级 | 优化器状态（Adam 是 2 倍参数） |

所以一次训练迭代 ≈ 3 倍前向计算 + 3 倍参数量的存储。

**推理只需要 1 倍计算、0 倍额外存储。**

## 四、为什么这个差别对 ZK 是致命的

电路的成本与「计算量」和「witness 大小」都成正比。

- 推理：witness = 输入 + 权重 + 中间激活；
- 训练：witness 还要加上「所有层的激活（供反向用）」+「所有梯度」+「优化器状态」。

后者可能是前者的 **5–10 倍**。而电路规模已经装不下推理了（`06/02/01`），训练就更不用说。

## 五、推理模式下的两个细节

**细节一：dropout 关闭**

训练时随机丢弃神经元（防过拟合），推理时全部保留（并按概率缩放）。所以推理是确定性的，训练不是。

**细节二：BatchNorm 用 running stats**

训练时用当前 batch 的统计量，推理时用累积的滑动平均。这也是「训练和推理行为不同」的经典例子（`07/05`）。

这两个细节对 ZK 的好处是：**推理路径上没有随机性，电路可以完全静态。**

## 六、一个实践中的坑

很多模型导出 ONNX 时，**忘了把模型设成 eval 模式**。

后果：

- dropout 还在生效 → 每次推理结果不同；
- BatchNorm 用 batch 统计而非 running stats → 单张图推理时统计量失真（batch size = 1 时方差为 0）。

在普通部署里这会导致「精度莫名下降」；在 ZK 里更严重 —— **同一个输入两次证明对不上**，因为 witness 不同。

**导出前必做：`model.eval()`。**

## 七、自检答案

> 问：说清「反向传播为什么上不了电路」，并举一个已有的折中做法。

答：反向传播要从损失往回逐层算梯度，必须保存前向时每一层的激活值，witness 会膨胀 5–10 倍；同时训练含随机性（初始化、dropout、数据顺序）和优化器状态（Adam 的两倍参数），电路无法静态表达。已有折中是「只证一步 SGD 更新」（把一次参数更新做成电路），或只对聚合这类纯加法操作做证明。

## 八、一句话记住

**推理是「算一遍」，训练是「算一遍、记住每一层、再倒着算一遍」。ZK 只受得了前者。**
