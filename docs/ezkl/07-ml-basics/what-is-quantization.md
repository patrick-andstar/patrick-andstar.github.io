# 什么是量化

> **支撑** ｜ 前置：07_机器学习预备/07_模型导出与ONNX

**一句话**：把 float32 的权重压成 int8/int16 这类整数，省内存、省算力，代价是精度。EZKL 更进一步，用定点整数。

## 一、为什么要量化

一个 FP32 权重占 4 字节，INT8 占 1 字节。

- 模型小 4 倍；
- 内存带宽省 4 倍；
- 整数乘加比浮点快（尤其在边缘设备）。

代价：精度下降。

## 二、两种量化

**对称量化**（EZKL 用的定点属于这类）：

> 真实值 ≈ q · s，其中 q 是整数，s 是 scale

- 零点固定为 0；
- 适合「关于 0 对称」的数据（权重）。

**非对称量化**：

> 真实值 ≈ (q − z) · s，其中 z 是零点

- 零点可以偏移；
- 适合「全正」的数据（ReLU 之后的激活）。

## 三、算一个具体的

假设某层权重范围是 [−2.0, 2.0]，要量化到 INT8（−128..127）。

对称量化：

> s = 2.0 / 127 ≈ 0.01575

- 权重 1.0 → q = round(1.0 / 0.01575) = 63
- 反量化：63 × 0.01575 = 0.992（误差 0.008）

误差约 0.8%，和 EZKL 的定点精度（`05/02/01`）同一量级。

## 四、和 EZKL 定点数的关系

| | 通用量化（如 PyTorch） | EZKL 定点 |
|---|---|---|
| 表示 | q · s，s 是任意浮点 | 整数 × 2^(−s) |
| scale | 可为任意值 | **必须是 2 的幂** |
| 运算 | 需要乘 s 再除 s | 只需移位 |
| 目的 | 省内存/加速 | **能在电路里用** |

**关键区别**：EZKL 强制 scale 是 2 的幂，因为电路里「除以 2^s」比「除以任意 s」便宜（`05/03/02`）。

所以你不能直接把 PyTorch 的量化模型丢给 EZKL —— 它会重新按 2 的幂量化。

## 五、精度损失能接受吗

经验值：

| 位宽 | 典型精度损失（ResNet 级） |
|---|---|
| FP32 | 基准 |
| INT8 | 0.1–1% |
| INT4 | 1–5% |

**注意**：这是「训练后量化（PTQ）」的数字。如果做「量化感知训练（QAT）」，损失可以更小。

EZKL 用的是 PTQ（先训好再量化），所以精度损失按上表估。

## 六、一个容易混的地方

「量化」和「定点」不是同义词，但经常混用。

- **量化**：把连续值映射到离散值（可以是 INT8、INT4、甚至二值）；
- **定点**：一种具体的量化方式，小数点位置固定。

EZKL 用的是「定点量化」：既是量化（离散），也是定点（scale 固定为 2^-s）。

## 七、自检答案

> 问：说清 float32 → int8 大概丢多少精度，以及为什么模型还能用。

答：INT8 有 256 个档位，对称量化时步长约 range/127，相对误差约 0.4%–0.8%。模型还能用是因为神经网络对小幅权重扰动不敏感（大量参数冗余、激活函数有饱和区），而且量化误差在层间近似独立、不会系统性放大。ResNet 级模型 INT8 量化通常只掉 0.1–1% 准确率。

## 八、一句话记住

**量化 = 用整数近似小数。EZKL 的特殊之处是 scale 必须是 2 的幂，因为电路只会移位。**
