> 读完约 7 分钟。这一篇把「哈希」从一个词拆成三种不同的保证。

## 一、先看它做什么

哈希函数把任意长的输入压成固定长的输出（SHA256 是 32 字节）。

但「压缩」本身不难（取前 32 字节就行）。哈希的价值在于三个**安全性质**，而这三个性质对应三种完全不同的用法。

## 二、三个性质，三种用法

| 性质 | 说的是 | 用来干什么 |
|---|---|---|
| **单向性**（原像抵抗） | 给 h，找不到 x 使 H(x)=h | 藏数据 |
| **抗碰撞性** | 找不到 x≠y 使 H(x)=H(y) | 绑定（承诺、Merkle 树） |
| **随机预言机** | 输出看起来真随机，与输入毫无关联 | 产生挑战（Fiat-Shamir） |

三者不是一回事：

- 抗碰撞**不蕴含**单向（理论上可以构造「碰撞很难但能反推」的函数）；
- 随机预言机是最强的假设，也是最不牢的（没人能证明 SHA256 真的像随机函数）。

实际用的哈希（SHA256、Keccak、Poseidon）都被认为同时满足三条。

## 三、抗碰撞到底有多强：生日攻击

如果哈希输出 n 位，你可能以为要试 2ⁿ 次才能撞上。**不用**。

因为找的是「任意两个输入的碰撞」，不是「撞上某个特定值」。根据生日悖论，只要试约 **2^(n/2)** 次就够了。

所以：

- SHA256 输出 256 位 → **碰撞安全只有 128 bit**；
- Poseidon 常用 254 位输出 → 碰撞安全约 127 bit。

写报告时说「SHA256 提供 256 位安全」是不严谨的，正确说法是「原像 256 bit、碰撞 128 bit」。ZK 里主要用碰撞安全，所以按 128 算。

## 四、随机预言机：为什么它能替验证者出题

理想化的哈希被当成一个「真随机函数」：任何人问它同一个问题，答案都一样；但答案和问题之间没有任何可利用的关系。

这条性质让 Fiat-Shamir 成立（`00/04`）：

- 证明者算挑战之前，猜不到结果 → 相当于验证者临场出题；
- 但所有人算出来都一样 → 验证者事后能复核。

**代价要说清**：这是一个假设，不是定理。历史上真的有协议因为「哈希用错方式」而被攻破（比如把长度可变的内容直接拼接，导致不同消息得到同一哈希前缀）。

## 五、在 EZKL 里

- **承诺**用哈希（要抗碰撞）：`Poseidon` 给公开输入做承诺（`05/04/03`）；
- **挑战**用哈希（要随机预言机）：halo2 的 transcript，每一步 absorb/squeeze；
- **文件校验**用 SHA256（要抗碰撞）：`srs_sha.rs` 校验 SRS 有没有被换过；
- **电路内部**几乎不用 SHA256：它每一位都要几百条约束，太贵。Poseidon 就是为此设计的（`02/01/03`）。

## 六、一个必须纠正的直觉

**哈希不是加密。**

- 加密：可逆，有密钥，能把密文还原成明文；
- 哈希：不可逆，没有密钥，永远还原不回去。

所以「用哈希藏数据」的意思是「藏得住，但也取不回来」——这在承诺里正好合用（你不需要取回，只需要事后能验证），但在需要还原的场景完全不适用。

## 七、自检答案

> 问：分别说出「藏数据」「产生挑战」「建 Merkle 树」各依赖哪个性质。

答：藏数据依赖单向性（反推不出输入）；产生挑战依赖随机预言机性质（输出不可预测且可复核）；建 Merkle 树依赖抗碰撞性（否则可以换掉叶子还得到同一个根）。

## 八、一句话记住

**一个哈希，三种用法：单向用来藏、抗碰撞用来绑、随机预言机用来出题。别混着说。**
