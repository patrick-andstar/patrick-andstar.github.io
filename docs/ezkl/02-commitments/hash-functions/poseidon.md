# Poseidon与zk友好哈希

> **核心** ｜ 前置：02_承诺与哈希/01_哈希函数/01_哈希的三个安全目标

**一句话**：专为电路设计的哈希：只用加法和 5 次幂，一位的约束数比 SHA256 少一到两个数量级。

**打个比方**：SHA256 像用几千块乐高拼一台计算器；Poseidon 像直接查乘法表。省的不是时间，是电路里的「零件数」。

> 读完约 7 分钟。这一篇讲一件事：为什么 ZK 里不用 SHA256。

## 一、先算一笔账

SHA256 在普通电脑上快到可以忽略——每秒几百万次。但在**电路里**，它贵得离谱。

原因：SHA256 是按「位」设计的。它要做 32 位整数的循环移位、按位与、按位异或。而在电路里：

- 一个 32 位整数，要么拆成 32 个域元素（每个一位），要么用一个域元素加范围检查（`05/02/04`）；
- 一次按位异或，在域上没法直接算，得展开成一堆约束；
- 一轮 SHA256 有 64 步，每步几十条约束。

结果：**一次 SHA256 压缩函数要几万条约束**。而整个小模型电路可能只有三万行。哈希一次，模型就装不下了。

## 二、Poseidon 的思路：只用「加」和「五次方」

Poseidon（2019 年提出）把哈希重新设计成电路友好的样子：

> 状态 = 几个域元素（常用 3 个）
> 每一轮：每个元素加一个常数 → 取 5 次方 → 用一个固定矩阵混合

没了。没有位运算、没有查表、没有循环移位。全是加法和乘法——**正是电路唯一会做的事**。

其中「取 5 次方」叫 S-box（替换盒），是唯一的非线性来源。非线性是哈希安全的必需品：全是线性运算的哈希，一眼就能被解出来。

## 三、省了多少

| | 一次哈希的约束量级 |
|---|---|
| SHA256 | 几万条 |
| Poseidon（宽度 3） | 几百条 |

差两个数量级。这就是全部理由。

在 `logrows = 16`（65536 行）的电路里，SHA256 一次就吃掉半张表，Poseidon 只占百分之一。

## 四、代价：它更便宜，不是更安全

这一点必须说清楚：

- Poseidon 的安全论证比 SHA256 新得多（2019 vs 2001），分析历史短；
- 它的代数结构强，理论上更容易受代数攻击；
- 参数（轮数、MDS 矩阵、轮常数）必须选对，有专门的分析文献。

所以「Poseidon 更安全」是错的。正确说法是：**在电路这个特定环境里，它是唯一划算的选择。**

## 五、在 EZKL 里

- 实现在 `src/circuit/modules/poseidon.rs`，底层用 `halo2_gadgets` 的 `Pow5Chip`；
- 用途一：给**公开输入做承诺**。当输入张量很大时，把它压成一个 Poseidon 哈希放进 instance，省掉随张量线性增长的群运算（`05/04/03`、`polycommit.rs`）；
- 用途二：`hashed` 可见性下，权重不进 circuit，只进一个哈希值。

注意它和 KZG 的分工：**KZG 承诺多项式，Poseidon 承诺张量**。前者给证明系统用，后者给数据用。

## 六、容易混的地方

「哈希友好」不等于「哈希弱」。

在普通场景（校验文件、算指纹）下，你仍然应该用 SHA256 —— 它成熟、有硬件加速、分析充分。Poseidon 只在「要在电路里算哈希」时才值得。

EZKL 自己也是这么分工的：`srs_sha.rs` 校验 SRS 文件用的是 SHA256，因为那一步在电路外。

## 七、自检答案

> 问：说清 Poseidon 为什么比 SHA256 省几十倍约束。

答：SHA256 按位设计，电路里每个位运算都要拆成域上的加减乘，一次压缩函数要几万条约束；Poseidon 只用「加常数 + 五次方 + 线性混合」，全是电路原生的运算，一次哈希只要几百条。省的是「把位运算翻译成域运算」这层开销。代价是安全分析历史短、参数敏感。

## 八、一句话记住

**Poseidon 不是更好的哈希，是电路里唯一付得起的哈希。**
