## 一、三层误差，别混着说

| 误差来源 | 量级 | 谁负责 |
|---|---|---|
| 定点量化 | 1/2^s | 量化参数 |
| 查表近似 | 1/2^bits | 表大小 |
| 逐层累积 | 随深度放大 | 端到端校准 |

三者叠加，才是「模型输出偏了多少」。

**关键**：这三种误差，ZK 一个都不管。ZK 只管「按这套规则算对了没有」（`05/02/03`）。

## 二、一个实用补丁：输出容差检查

思路极简单：

1. 把「参考输出」`y_ref` 作为**公开输入**；
2. 证明者提交 `y_proven`（电路算出来的）；
3. 验证方自己算：`|y_proven − y_ref| ≤ ε`。

**电路一行都不用改。**

为什么这不算作弊？因为：

- ZK 仍然保证 `y_proven` 是「用声明的模型、声明的定点规则」算出来的；
- 容差检查是**额外**的一层约束，由验证方在电路外执行；
- 攻击者不能靠伪造 `y_proven` 通过，因为一旦伪造，ZK 就过不了。

## 三、ε 该取多少

三种取法，从松到紧：

**取 0**：要求完全相等。只适合「参考实现和电路用同一套定点算术」的场景（比如你自己写的 PyTorch 量化模拟）。

**取量化误差上界**：`ε = N × 2^(−s)`，N 是层数。理论上能兜住，但很松。

**取实测分布**：跑 1000 个样本，看误差的 99 分位，再乘 2 倍余量。**最实用。**

本项目建议用第三种，并在报告里写清「ε 由 1000 个样本的 99 分位确定」。

## 四、为什么这个补丁比「加宽电路」划算

| 方案 | 成本 | 效果 |
|---|---|---|
| 加宽 bits / 加大 scale | 行数翻倍，可能跨 k | 减少误差，但不消除 |
| 输出容差检查 | **几乎为零**（一次减法 + 比较） | 明确兜住「偏太多」的情况 |
| 逐层区间断言 | 每层加约束，行数显著增加 | 定位到具体层，但工程量大 |

所以正确的顺序是：**先做容差检查（保底），再看要不要加宽（优化）。**

## 五、一个必须说清的边界

容差检查有个前提：**`y_ref` 本身得可信。**

如果 `y_ref` 是证明者自己算的，那这个检查毫无意义 —— 他可以把错的 `y_ref` 一起提交。

所以 `y_ref` 必须来自：

- 验证方自己算的（他有模型和输入）；
- 或者来自一个独立可信的执行环境（TEE、另一个证明）；
- 或者来自链上已存的基准结果。

**这是这套方案唯一的软肋，写方案时必须点明。**

## 六、在 EZKL 里怎么落地

不需要改电路，只需要：

1. `gen-witness` 时把 `y_ref` 一起写进公开输入（v23 里它是 `proof.json` 的 `instances` 字段）；
2. 验证方拿到 proof 后，先跑 `verify`，再跑自己的容差比较；
3. 两步都过，才认为这次推理可接受。

注意：`y_ref` 进 instances 会让公开输入变大（多一份输出张量），但输出的规模通常远小于输入，成本可以接受。

## 七、自检答案

> 问：说清「怎么把容差检查挪到电路外」，并写出验证方的判定式。

答：把参考输出 y_ref 作为公开输入（instance），电路仍然只算 y_proven；验证方在 verify 通过之后，自己计算 `|y_proven − y_ref| ≤ ε`（逐元素），全部满足才接受。判定式是 `verify(vk, proof, instances) == true ∧ ∀i: |y_proven[i] − y_ref[i]| ≤ ε`。前提是 y_ref 来自可信来源，否则检查无意义。

## 八、一句话记住

**电路证「算得对」，容差证「算得准」。两层分开，各管各的，成本最低。**
