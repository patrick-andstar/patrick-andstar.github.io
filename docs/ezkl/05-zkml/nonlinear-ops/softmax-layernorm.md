# Softmax与LayerNorm

> **核心** ｜ 前置：05_zkML层/03_非线性算子/02_除法与倒数

**一句话**：两者都要「除以一个和或标准差」，是整张图里最贵的部分之一，也是行数暴涨的常见原因。

**打个比方**：这两层最贵的不是乘法，是「先全部加起来再除」。电路里没有除法，只能查表或先猜一个商再乘回去验。

**在 EZKL 里的落点**：LookupOp::Sqrt / Div；softmax 的查表实现。

## 一、它们长什么样

**Softmax**（把一排分数变成概率）：

> softmax(x)ᵢ = e^(xᵢ − max) / Σⱼ e^(xⱼ − max)

**LayerNorm**（把一层的输出标准化）：

> LN(x) = (x − μ) / √(σ² + ε)，其中 μ = mean(x)，σ² = var(x)

两个式子有三个共同点：

1. 都要**对整个张量求和**（μ、σ²、分母）；
2. 都要**除法**；
3. LayerNorm 还要**开方**。

## 二、为什么减去 max

Softmax 里那个 `− max` 不是数学需要，是**数值稳定**需要。

e^1000 会溢出。减去最大值后，最大的那一项变成 e⁰ = 1，其余都 ≤ 1，绝对不会溢出。

在定点电路里这一条更关键：**没有减 max 的 softmax，几乎必然溢出**（`05/02/03`）。

代价：多一次全局最大值查找（MaxPool 那类操作，`05/01/02` 说过它很贵）。

## 三、成本拆开看

以一层 512 个元素为例：

| 操作 | 电路里怎么实现 | 成本 |
|---|---|---|
| 求和 Σ | 逐元素累加 | 512 行（每行一次加法） |
| 减 max | 逐元素减法 | 512 行 |
| e^x | 查表 | 512 次查询 |
| 除以分母 | 查表除法（或猜商） | 512 次查询 |
| 开方（LayerNorm） | 查表 | 512 次查询 |

**关键洞察**：除法不能「算一次然后大家共用」，因为**分母相同但被除数不同**，每个元素都要单独做一次除法。

所以 LayerNorm 的成本是 O(N) 次除法，而除法在电路里是最贵的原语之一（`01/01/02`）。

## 四、和卷积比一下

一层 3×3 卷积、64 通道、56×56：

- 乘加次数：约 1.15 亿；
- 但每次乘加只是「一行里的一个门」，可以高度并行；
- 摊到行数上，约 2900 万行（`05/01/03`）。

一层 LayerNorm，512 个元素：

- 约 2000 次操作；
- 但每次都是除法或开方，每个要占几行；
- 约 5000–10000 行。

单看数字，卷积大得多。**但卷积是可以优化的（矩阵乘、并行），除法不行** —— 它必须逐个查表，而且每次查询都要走一遍查找论证。

所以在 zkML 的实际瓶颈里，归一化层的「单位成本」远高于卷积层。

## 五、在 EZKL 里

- `LookupOp::Sqrt`、`LookupOp::Div` 提供开方和除法；
- Softmax 的实现要拆成「max → 减 → exp 查表 → 求和 → 除」五步；
- 每一步都会产生新的中间张量 → 新的行、新的范围检查。

**实践建议**：如果模型能用 ReLU + BatchNorm（可折叠进卷积），就别用 LayerNorm + GELU。前者在电路里便宜一个数量级。

## 六、自检答案

> 问：说清 LayerNorm 为什么要先算均值和方差，以及它在电路里贵在哪。

答：LayerNorm 要把每个元素减去均值再除以标准差，所以必须先对整个张量求 μ 和 σ²（两次全局求和）。贵在两处：一是全局求和需要逐元素累加、无法并行压缩；二是「除以标准差」对每个元素都要单独做一次除法（分母相同但被除数不同），而除法在电路里要靠查表或猜商，单位成本很高。

## 七、一句话记住

**卷积贵在总量，归一化贵在单价。除法不能并行摊销，所以每个元素都要付一次。**
