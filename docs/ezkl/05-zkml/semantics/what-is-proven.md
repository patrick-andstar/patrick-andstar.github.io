# 证明的到底是什么

> **核心** ｜ 前置：05_zkML层/02_定点量化/03_溢出为何仍能出合法证明

**一句话**：y = f(x; w) 这一次计算的完整性。不证「模型好」、不证「数据真」、不证「训练过程」。

**在 EZKL 里的落点**：整个项目的 statement 定义。

## 一、那句话

EZKL 的 statement，准确写法是：

> **存在一组 witness w，使得电路 C 在公开输入 x 上计算出公开输出 y，即 C(x, w) = y。**

拆开看：

- `C`：编译好的电路（模型结构 + 定点算术规则 + 查找表）；
- `x`：公开输入（能公开的那部分，比如输出，或者输入+输出）；
- `w`：私有部分（权重、中间值、以及没公开的输入）；
- `y`：公开输出。

**它证的是「这一次计算的完整性」。**

## 二、它明确不证的四件事

| 不证 | 为什么 |
|---|---|
| 模型准不准 | ZK 不知道训练集，也不知道准确率 |
| 数据真不真 | 输入可以是伪造的，ZK 只管「按这个输入算了」 |
| 权重是不是你的 | 没有身份绑定，除非另加签名 |
| 训练过程规不规范 | 训练上不了电路（`05/04/04`） |

这四条经常被人混进「可验证 AI」的宣传里，要分清。

## 三、三种「完整性」，别混着卖

| 层次 | 问的问题 | 用什么证 |
|---|---|---|
| **文件完整性** | 这个模型文件被改过吗 | 哈希 / 签名（毫秒级） |
| **执行完整性** | 这次推理真的按这个模型跑了吗 | ZK（秒级证明、毫秒级验证） |
| **结果正确性** | 输出对不对 | 容差检查 / 基准对比（`05/03/04`） |

哈希类方案只能做到第一层。它防不住「计算方换了另一套逻辑算，但文件哈希没变」—— 这正是 ZK 的独占价值。

反过来，ZK 也做不到第一层的「文件没被改」这件事的**低成本版本**：它证明的是「电路对应这份模型」，而不是「磁盘上那个文件没变」。两者需要配合。

## 四、为什么这个区分对你项目重要

你的指标里有两条：

1. 模型参数/模型文件完整性验证；
2. 模型推理过程完整性验证。

**这两条必须拆开讲**，因为它们在 EZKL 里对应不同配置：

- 第 1 条 → `param_visibility=fixed`（vk 绑定权重）；
- 第 2 条 → 任何配置都行（ZK 天然保证）。

而 `fixed` 与「联邦学习每轮换模型」互斥（`04/03/05`）。所以方案里必须写清：哪一条用 ZK，哪一条用哈希，以及两者怎么咬合。

## 五、一个精确的表述模板

如果要写进技术文档，建议这么写：

> 本系统对每次推理生成零知识证明，证明「存在一组权重与中间值，使得在声明的定点算术规则下，电路对给定输入产生了给定输出」。该证明保证**执行完整性**；模型文件的**完整性**由 SHA256 哈希与 vk 绑定共同保证；**结果正确性**由输出容差检查保证。

三句话，三个机制，互不越界。评审问起来也不会露怯。

## 六、自检答案

> 问：用一句话写出 EZKL 的 statement，并列出它明确不覆盖的三件事。

答：存在一组 witness w，使得电路 C 在公开输入 x 上输出公开输出 y（C(x,w)=y）。它不覆盖：模型准确率（不知道训练数据与真实标签）、输入数据的真实性（输入可以是伪造的）、权重归属（没有身份绑定）。另外也不覆盖训练过程的规范性。

## 七、一句话记住

**ZK 证「这次算对了」，不证「模型好」「数据真」「权重是你的」。三件事要三套机制。**
