# 公开输入的承诺化

**一句话**：公开输入太大时，用 Poseidon 哈希或 KZG 承诺把它压掉，省下随张量线性增长的验证开销。

## 一、问题：公开输入会让验证变慢

回忆 `04/03/04` 的结论：验证的计算量与电路行数无关，但与**公开输入的数量**有关。

因为 instance 里的每个值都要参与群运算（把它们绑进证明）。N 个公开输入 → N 次标量乘 → 验证时间线性增长。

具体量级（按本项目纯验证 3 ms 反推，每次标量乘约微秒级）：

| 公开输入数量 | 验证计算量级 |
|---|---|
| 10 | 几毫秒 |
| 1,000 | 仍是毫秒级 |
| 100,000 | 几十到几百毫秒 |
| 1,000,000 | 秒级 |

**注意**：这是「计算」的增长，不含启动与读盘（那部分固定约 65 ms）。所以 10 万公开输入时，端到端才是真的顶到 1 秒。

## 二、两条路，别混

EZKL 里有两种「不把原值放进公开区」的机制，我上一版把它们写成了一个，这里分开：

| | `hashed` | `polycommit`（枚举 `KZGCommit`） |
|---|---|---|
| 用什么 | **Poseidon 哈希** | **KZG 承诺** |
| 产出 | 32 字节的域元素 | 一串 33 字节的 G1 点 |
| 数量 | 固定 1 个 | 随张量变大（每 n 个值一个点，n≈2^k） |
| 电路内开销 | 一次 Poseidon（约几百条约束） | 不在电路里算哈希；承诺由模块路径产出 |
| 文件 | `poseidon.rs` | `polycommit.rs`（**头注释写错了，说自己是 Poseidon，实际调 `commit_lagrange`**） |

**记法**：hashed 是贴指纹，polycommit 是贴封条。一个是哈希，一个是曲线点。

## 三、`hashed` 怎么工作（这条我确定）

1. 原文留在 advice 列里，参与计算；
2. 同时算一个 Poseidon 哈希，按配置进公开区（`hashed/public`）或回灌计算图（`hashed/private/{outlets}`）；
3. 验证者能确认「你用的是某个特定值」，但看不到值本身。

代价是电路里多一次 Poseidon。

## 四、`polycommit` 怎么工作（这条只到我能证的程度）

`PolyCommitChip::commit(message, num_unusable_rows, params)` 做的是：

1. 把消息按 `n = 2^k − unusable_rows` 切段；
2. 每段当多项式系数，调 `params.commit_lagrange`；
3. 返回 `Vec<G1Affine>`。

所以它给出的是**真正的 KZG 承诺**，不是哈希。

**但我没能在 `src/` 里找到「电路内校验这个承诺」的 gate。** `module_requires_polycommit()` 只说明它是一条独立路径。所以我只能写到这：**它产出承诺点、由模块处理；绑定细节未追清**。要用它，先自己跑一遍 `ezkl.polycommit` 再写进方案，别照抄文档。

## 五、什么时候值得做

粗略判断（按本项目数字）：

| 公开输入规模 | 建议 |
|---|---|
| < 1,000 | 别折腾，直接 public |
| 1,000 – 100,000 | 值得，hashed 一次几百约束换掉线性增长 |
| > 100,000 | 必须做，否则端到端必超 1 秒 |

**但注意一个前提**：承诺化只是把「公开输入」换成「承诺」，`y_ref` 这类必须给验证者看的参考值还是要放公开区。所以真正能压的是「中间张量、大批量输入」，不是「最终结论」。

## 六、一个容易漏的细节

哈希的顺序必须固定。

同一个张量，按行展平还是按列展平，哈希不同。所以：

- 证明方与验证方必须约定同一展平顺序；
- 换框架（PyTorch → ONNX → EZKL）时这一步最容易出岔子；
- 出岔子的表现是「哈希对不上」，不是「证明失败」——排查时容易误判成哈希实现有问题。

## 七、自检答案

> 问：`hashed` 和 `polycommit` 各自省下的是什么？代价分别在哪？

答：`hashed` 把一个大张量压成 32 字节哈希，省的是公开区体积与验证时的群运算，代价是电路里多一次 Poseidon（几百条约束）。`polycommit` 用 KZG 承诺替代哈希，产出的是若干 G1 点（数量随张量增长），省掉电路内的哈希计算，代价是承诺点更多、验证要做 MSM，且绑定细节在源码里我没追清。

## 八、一句话记住

**hashed 贴指纹（32 字节哈希），polycommit 贴封条（一串曲线点）。前者便宜，后者不确定，别混着用。**
